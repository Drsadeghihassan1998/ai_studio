# طرح جامع بازطراحی بصری نرم‌افزار مالی داروخانه

ارتقای طراحی بصری نرم‌افزار به سبک مدرن، مینیمال و منطبق با استانداردهای نرم‌افزارهای سلامت و مالی، با تمرکز بر نوار ناوبری کناری و پایینی، کارت‌های شاخص داشبورد، پالایش سایه‌ها و خطوط حاشیه، و هماهنگی کامل حالت روشن و تاریک بدون هیچ‌گونه دستکاری در محاسبات و منطق مالی برنامه.

> [!IMPORTANT]
> **تصمیم‌های تأییدشده در فاز گفتگو:**
> ۱. **سبک بصری:** مدرن، مینیمال و منطبق با استانداردهای سامانه‌های بالینی و دارویی.
> ۲. **محدودهٔ اولویت:** بازطراحی جامع پوسته و نوار ناوبری (Shell)، صفحه داشبورد و قطعات مشترک کارت‌ها (KeyCard، Card).
> ۳. **پالت رنگ:** حفظ هویت سبز دارویی اصلی برنامه (Pharmacy Green / Teal) با بهبود مرزها، کنتراست متنی، لایه‌های سطحی و سایه‌های ظریف (`--shadow`).
> ۴. **حفظ استقلال و پایداری:** تمامی ساختارهای ذخیره‌سازی محلی (Dexie/IndexedDB)، محاسبات در `src/lib/calc.ts` و خروجی تک‌فایلی مستقل بدون تغییر می‌مانند.

---

## ۱. مرور کلی و اهداف بازطراحی

- **هدف:** تبدیل رابط کاربری به یک محیط کاری شیک، چشم‌نواز و آرامش‌بخش برای داروساز و پزشک، بدون شلوغی‌های بصری، با بیشترین خوانایی برای اعداد ریالی و ترازهای مالی.
- **مخاطب هدف:** پزشک و داروساز که روزانه نیاز به بررسی سریع نقدینگی، سود ماهانه و چک‌ها در فضایی تمیز و حرفه‌ای دارند.
- **ارزش کلیدی:** کاهش خستگی چشم، تفکیک شفاف شاخص‌های حیاتی از داده‌های ثانویه، و ارتقای حس اطمینان و دقت محاسباتی.

---

## ۲. تجربهٔ کاربری و معماری بصری

### الف) ساختار پوسته و ناوبری (Shell)
- **ستون کناری (Sidebar Desktop):**
  - بازطراحی بخش عنوان و نشان داروخانه با یک محفظهٔ آیکون خوش‌تراش با گرادیان خفیف سبز دارویی و فونت ضخیم روان.
  - چینش دسته‌بندی‌شده یا فاصله‌گذاری تمیزتر آیتم‌های منو با انیمیشن ملایم تغییر رنگ پس‌زمینه در حالت انتخاب (`bg-primary/10` به همراه نوار نشانگر فعال باریک).
  - کلید تبدیل واحد پول (تومان / ریال) با دکمه‌های قطعه‌بندی‌شدهٔ مسطح و مدرن‌تر (Segmented Pill).
- **نوار ناوبری موبایل (Mobile Bottom Bar):**
  - دکمه‌های با ارتفاع و منطقه لمسی استاندارد (حداقل ۴۸ پیکسل) همراه با بازخورد بصری لمس، آیکون‌های متناسب و متن ظریف با فاصله مناسب از لبهٔ امن صفحه.
- **کشو (Drawer):**
  - سایهٔ محو پس‌زمینه و لبه‌های ملایم بالا در موبایل و گوشه‌های تمیز در دسکتاپ.

### ب) داشبورد و کارت‌های شاخص (KeyCards & Dashboard)
- **کارت‌های پنج‌گانه شاخص:**
  - تفکیک کارت «سود این ماه» و «موجودی نقد» به عنوان شاخص‌های پیشتاز با تایپوگرافی برجسته (`text-key font-bold tabular-nums`) و برچسب‌های متنی خوانا.
  - بهبود وضعیت کارت «پولم کی کم می‌آید؟» با بج‌های ملایم، کنتراست استاندارد و برچسب‌های توضیحی خوانا.
  - دکمهٔ راهنمای محاسبه (`HowCalculated`) به صورت دکمهٔ ملایم و هماهنگ در گوشهٔ بالایی هر کارت.
- **فهرست چک‌های نزدیک:**
  - استفاده از سطرهای شفاف با خطوط مرزی مویی (Hairline Dividers: `1px solid var(--line)`)، برچسب‌های تمیز سررسید و هم‌ترازی ارقام ریالی به صورت ستونی (`tabular-nums`).
- **بخش مراحل شروع به کار:**
  - طراحی چک‌لیست خوش‌فرم با چک‌باکس‌های گرد زیبا و دکمهٔ اصلی پررنگ برای هدایت کاربر.

### ج) پالت رنگ، متغیرها و حالت تاریک (Design Tokens)
- **در `src/index.css`:**
  - بهبود متغیر `--primary` و لایه‌های سایه `--shadow` (استفاده از سایه‌های طبیعی چندلایه‌ای ملایم به جای سایه‌های کدر).
  - تثبیت تراز رنگ در حالت تاریک (`--bg`، `--card`، `--line`) برای پیشگیری از هرگونه افت کنتراست یا کنتراست شدید زننده.
  - پایبندی کامل به قانون ۶۰-۳۰-۱۰ (۶۰٪ بوم خنثی، ۳۰٪ کارت‌ها و سطوح سازه‌ای، ۱۰٪ رنگ سبز تاکیدی).

## ۳. تصمیم‌های فنی و اجتناب از خطاهای رایج

```
┌─────────────────────────────────────────────────────────────┐
│                    پوستهٔ برنامه (Shell)                     │
│  ┌────────────────────┬──────────────────────────────────┐  │
│  │ ستون ناوبری کناری   │ هدر: تبدیل واحد (تومان/ریال)      │  │
│  │  - نشان داروخانه   │      نشانگر داده نمونه (در صورت)   │  │
│  │  - آیتم‌های فعال   ├──────────────────────────────────┤  │
│  │  - وضعیت انتخاب    │ محتوای صفحه:                     │  │
│  │                    │  ┌────────────────────────────┐  │  │
│  │                    │  │ کارت‌های شاخص مالی (KeyCard)│  │  │
│  │                    │  ├────────────────────────────┤  │  │
│  │                    │  │ لیست چک‌ها و اقدامات گام‌به‌گام│ │  │
│  │                    │  └────────────────────────────┘  │  │
│  └────────────────────┴──────────────────────────────────┘  │
└─────────────────────────────────────────────────────────────┘
```

- **تضمین عدم شکست محاسبات:** فایل‌های منطقی از جمله `src/lib/calc.ts` و `src/lib/cashflow.ts` دست‌نخورده باقی می‌مانند.
- **تضمین تست‌ها:** تمامی آزمون‌های Vitest پس از بازطراحی استایل‌ها مجدداً اجرا و اعتبارسنجی می‌شوند (`npm test`).
- **خروجی نهایی:** ساخت آزمایشی فایل تک‌فایلی (`npm run build`) برای حصول اطمینان از عملکرد صددرصد آفلاین.

## ۴. مراحل گام‌به‌گام اجرا پس از تأیید

۱. **مرحله ۱:** به‌روزرسانی توکن‌های استایل و متغیرهای رنگ و سایه در `src/index.css` (پالایش سایه‌ها، مرزها، و رنگ‌های تم تاریک و روشن).
۲. **مرحله ۲:** نوسازی کامپوننت‌های پایهٔ UI در `src/components/ui/basics.tsx` (طراحی تمیزتر Card، KeyCard، Segmented، Button و Badge).
۳. **مرحله ۳:** ارتقای چیدمان پوسته در `src/components/layout/Shell.tsx` (ناوبری کناری و موبایل، سربرگ و نشان برند).
۴. **مرحله ۴:** بهینه‌سازی بصری صفحهٔ `src/components/Dashboard.tsx` (فاصله‌گذاری‌ها، تایپوگرافی اعداد و کارت‌های وضعیت).
۵. **مرحله ۵:** اجرای `npm run typecheck`، `npm test` و `npm run build` و ارائهٔ گزارش فایل‌های تغییریافته و چک‌لیست تست به زبان ساده.
